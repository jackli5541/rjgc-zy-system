# AI 教师与批改修复交付

## 变更

- AI 老师和 AI 批改共用同一套接口地址、API Key、模型和超时，保留独立启用开关和输出上限。配置迁移详见 `AI独立配置.md`。
- AI 教师生成标准 UUID v4，完成事件与历史恢复兼容无连字符及大小写差异，真正缺少对应回答时仍报告错误。
- 纯问候（你好、您好、老师好、叶老师你好、hi、hello 等，兼容首尾空格与常见标点）固定回复“你好！你想了解哪个课程概念或作业要求？”，不调用模型，仍通过 delta、done 保存问答。带课程问题的问候走正常模型回答。普通问题按复杂度简答，不降低输出上限。
- 批改精简最多一次、最多五秒，并受任务剩余时间限制；精简失败保留有效主结果。保留 JSON、等级和证据校验及运行 ID 防覆盖。
- 增加任务、运行、处理进程及阶段耗时日志。AI 面板在学生互评与批注下方，仅教师可编辑批阅时显示，学生端不显示或启动 AI 批改。历史对比使用“上次 AI 建议”。

## 部署

1. 将旧模块专用接口配置迁移为公共 `AI_*`，不要覆盖客户整份 `.env`。
2. 统一升级并重启全部 API 与 Worker；本次无新数据库迁移。
3. 在 `frontend` 执行 `npm run build`，部署完整 `frontend/dist`，核对浏览器加载的新资源；该目录按仓库规则不提交 Git。

真实配置、密钥、本地数据库、备份、演示数据和日志不属于交付文件。客户服务器未被修改。

## 验证与限制

49 项后端模拟单元测试、30 项前端单元测试通过；前端生产构建及差异检查通过。新增了数据库问候回归用例，但按仓库约定需在 Compose 测试环境运行，目前未运行该组数据库测试或 E2E。

另在独立本地验收库手动验证了实际问候路由：模型客户端拦截为零调用，delta、done 正常，历史保存两条问答。真实批改、重新生成和短课程问答曾通过完整业务页面或接口验证，学生批改请求为 403；这些结果不保证客户模型、代理或网络在所有请求中均正常，客户此前失败截图的具体异常仍未完全确认。
