# 正式版 MVP 验收说明

## 初始状态

执行 `scripts/init-local.ps1` 和 `scripts/start-local.ps1` 后访问 <http://localhost:8080>。开发环境仅 PostgreSQL 在 Docker 中运行，前后端在本机运行。使用固定教师账号 `teacher / 123456` 登录；系统应显示空教学班状态，不能出现示例学生、小组、作业或成绩。

## 主流程

1. 教师创建教学班，上传包含“学号、姓名”列的 CSV 或 XLSX；XLSX 的名单表可以不是当前激活工作表。先预览校验再确认导入，并验证成员搜索、单独新增、查看、修改姓名、重置密码和移出。
2. 新学生使用“学号 / 学号”登录。未入组时只能看到组队页面，其他业务导航不可见且 URL 无法绕过。
3. 一名学生创建小组，另一名学生申请加入；组长同意后，申请人自动解锁导航并进入教学班首页。
4. 教师发布个人作业，两名同组学生分别上传并正式提交，检查版本号、提交时间和撤回规则。
5. 教师为个人作业开启组内作品互评；学生只能选择同组其他成员已正式提交的作品，完成量表和评语后提交。
6. 被评价学生在公开范围内查看实名分数和评语；教师查看统计并可填写原因作废评价。
7. 教师保存或发布成绩，学生只能看到已发布给本人的成绩；通知和审计记录同步生成。

## 自动验证

`docker compose --profile test run --rm test-api pytest -q` 覆盖空库、名单创建账号、入组门禁、申请审批、小组草稿、个人提交、文件授权、跨成员作品互评、成绩留痕和归档限制。`docker compose --profile test run --rm e2e` 在官方 Playwright 容器中检查桌面与移动视口的空登录表单、顶部唯一导航和教师空工作台。自动测试使用独立的 `coursework_test` 数据库和临时文件系统，不接触开发运行数据；前端必须通过 Docker 生产构建。
