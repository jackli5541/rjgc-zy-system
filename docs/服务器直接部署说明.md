# 服务器直接部署说明

> 适用范围：Linux 单机首版部署  
> 原则：开发时 PostgreSQL 使用 Docker、前后端本地运行；自动化测试使用 Docker；生产服务器由 FastAPI 单端口提供 API 和前端页面

## 1. 运行组件

构建机安装 Node.js 22，生产服务器只需安装 Python 3.13 和 PostgreSQL 17，不需要 Node.js 或 Nginx。Office 文件仅提供鉴权后的原文件下载，不需要安装 LibreOffice。FastAPI 同时提供 API 与 Vue 构建产物，并与任务进程使用同一代码和 Python 虚拟环境，由 systemd 分别托管。

建议目录：

```text
/opt/coursework/app/        # 发布代码
/opt/coursework/venv/       # Python 虚拟环境
/var/lib/coursework/files/  # 私有文件
/var/log/coursework/        # 应用日志
```

## 2. 构建和部署前端

```bash
cd /opt/coursework/app/frontend
npm ci
npm run build
```

构建可在开发机或 CI 中完成。部署前端时只需要复制生成的 `frontend/dist`，生产服务器不需要前端源码、`node_modules` 或 Node.js。默认情况下，FastAPI 直接读取仓库内的 `frontend/dist`；也可通过 `FRONTEND_DIST` 指向复制后的绝对路径。

Windows 服务器可运行 `scripts\start-server.bat`，脚本默认把后端指向仓库内最新的 `frontend\dist`；独立存放 dist 时，将路径作为第一个参数，例如 `scripts\start-server.bat D:\coursework\dist`。可通过 `PYTHON_EXE`、`COURSEWORK_HOST`、`COURSEWORK_PORT` 和 `COURSEWORK_WORKERS` 覆盖启动参数。

`index.html` 禁止强缓存，Vite 生成的带哈希 `/assets` 文件缓存一年。响应大于 1 KiB 的 HTML、JavaScript、CSS、JSON 和其他可压缩内容会使用 gzip（客户端必须发送 `Accept-Encoding: gzip`）。图片、压缩包、字体等已压缩格式不会重复压缩。

`/api/v1/events` 是登录后的 SSE 实时更新入口。gzip 中间件会排除 `text/event-stream`，因此事件不会被压缩或缓冲。API worker 通过 PostgreSQL `LISTEN/NOTIFY` 共享事件，因此使用多个 Uvicorn worker 时无需增加 Redis。

## 3. 安装后端

```bash
python3.13 -m venv /opt/coursework/venv
/opt/coursework/venv/bin/pip install -r /opt/coursework/app/backend/requirements.txt
```

通过环境文件注入 `DATABASE_URL`、`FILE_ROOT`、`FRONTEND_DIST` 和 `SECURE_COOKIES`，其中数据库地址使用 `postgresql+psycopg://用户:密码@主机:5432/数据库`，不将生产密码写入仓库。同源部署无需额外配置 CORS。Office 文件直接提供鉴权下载，无需配置转换器。单文件上限默认 `MAX_FILE_SIZE_BYTES=104857600`（100 MB），如需调整须同时评估内存、磁盘空间与备份容量。首次部署或每次升级先执行：

```bash
cd /opt/coursework/app/backend
/opt/coursework/venv/bin/alembic upgrade head
/opt/coursework/venv/bin/python -m app.bootstrap
```

迁移与幂等初始化成功后启动 API：

```bash
cd /opt/coursework/app/backend
/opt/coursework/venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2
```

任务进程启动命令：

```bash
cd /opt/coursework/app/backend
/opt/coursework/venv/bin/python -m app.worker
```

将两条命令分别配置为 systemd 服务，使用专用的非特权用户运行，并设置 `Restart=on-failure`。服务器安全组或防火墙只开放实际访问端口和必要的 SSH 端口，不要开放 PostgreSQL 端口。

如果直接通过 HTTP 访问，设置 `SECURE_COOKIES=false`。公网部署应启用 HTTPS，此时设置 `SECURE_COOKIES=true`，并在 Uvicorn 启动参数中加入 `--ssl-keyfile` 和 `--ssl-certfile`；证书续期后需要重启 API 服务。也可以由云负载均衡或服务器面板终止 HTTPS，但必须确认它不会缓冲 SSE，并正确转发长时间上传请求。

## 4. 发布检查

1. 备份 PostgreSQL 与私有文件目录。
2. 更新代码并安装锁定版本依赖。
3. 执行 `alembic upgrade head` 和 `python -m app.bootstrap`；成功后再重启 API 和任务进程。
4. 构建前端，确认 `frontend/dist/index.html` 存在，再重启 API。
5. 检查 `/health/live`、`/health/ready`、首页和一个前端子路由。
6. 以教师、学生账号各完成一次登录和只读页面冒烟测试。
7. 登录后确认 `/api/v1/events` 保持连接、约每 15 秒收到心跳，并在另一账号提交作业后当前页面无需手动刷新即可更新。

上线前必须替换数据库密码、启用 HTTPS 与 Secure Cookie，并按实际数据量完成备份恢复和性能验收。DOCX/XLSX 不做转码，始终通过应用鉴权后下载原文件。
