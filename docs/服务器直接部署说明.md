# 服务器直接部署说明

> 适用范围：Linux 单机首版部署  
> 原则：开发时 PostgreSQL 使用 Docker、前后端本地运行；自动化测试使用 Docker；生产服务器直接运行各进程

## 1. 运行组件

生产服务器直接安装 Node.js 22、Python 3.13、PostgreSQL 17 和 Nginx。Office 文件仅提供鉴权后的原文件下载，不需要安装 LibreOffice。FastAPI 与任务进程使用同一代码和 Python 虚拟环境，由 systemd 分别托管。

建议目录：

```text
/opt/coursework/app/        # 发布代码
/opt/coursework/venv/       # Python 虚拟环境
/var/lib/coursework/files/  # 私有文件
/var/log/coursework/        # 应用日志
```

## 2. 构建前端

```bash
cd /opt/coursework/app/frontend
npm ci
npm run build
sudo rsync -a --delete dist/ /var/www/coursework/
```

Nginx 托管 `/var/www/coursework`，将 `/api/`、`/health/`、`/docs` 和 `/openapi.json` 反向代理至 `127.0.0.1:8000`。配置结构可直接参照 `frontend/nginx.conf`，并在生产环境补充 HTTPS、域名和访问日志。上传入口必须保留 `client_max_body_size 1g`，并将代理读写超时设置为至少 3600 秒，避免大文件上传被网关提前中断。

## 3. 安装后端

```bash
python3.13 -m venv /opt/coursework/venv
/opt/coursework/venv/bin/pip install -r /opt/coursework/app/backend/requirements.txt
```

通过环境文件注入 `DATABASE_URL`、`CORS_ORIGINS`、`FILE_ROOT` 和 `SECURE_COOKIES=true`，其中数据库地址使用 `postgresql+psycopg://用户:密码@主机:5432/数据库`，不将生产密码写入仓库。Office 文件直接提供鉴权下载，无需配置转换器。单文件上限默认 `MAX_FILE_SIZE_BYTES=104857600`（100 MB），如需调整须同时评估 Nginx、磁盘空间与备份容量。首次部署或每次升级先执行：

```bash
cd /opt/coursework/app/backend
/opt/coursework/venv/bin/alembic upgrade head
/opt/coursework/venv/bin/python -m app.bootstrap
```

迁移与幂等初始化成功后启动 API：

```bash
cd /opt/coursework/app/backend
/opt/coursework/venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 2
```

任务进程启动命令：

```bash
cd /opt/coursework/app/backend
/opt/coursework/venv/bin/python -m app.worker
```

将两条命令分别配置为 systemd 服务，使用专用的非特权用户运行，并设置 `Restart=on-failure`。

## 4. 发布检查

1. 备份 PostgreSQL 与私有文件目录。
2. 更新代码并安装锁定版本依赖。
3. 执行 `alembic upgrade head` 和 `python -m app.bootstrap`；成功后再重启 API 和任务进程。
4. 构建并原子替换前端静态文件。
5. 检查 `/health/live`、`/health/ready` 和 Nginx 配置。
6. 以教师、学生账号各完成一次登录和只读页面冒烟测试。

上线前必须替换数据库密码、启用 HTTPS 与 Secure Cookie，并按实际数据量完成备份恢复和性能验收。DOCX/XLSX 不做转码，始终通过应用鉴权后下载原文件。
