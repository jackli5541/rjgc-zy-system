# 作业、组内互评与教师评分接口

所有路径使用 `/api/v1` 前缀，并沿用会话 Cookie 与写请求 `X-CSRF-Token` 校验。

## 作业提交

- `POST /assignments`、`POST /assignments/bulk` 创建作业；互评仅适用于个人作业。
- `POST /assignments/{id}/files` 上传附件；学生上传的文件用途为 `SUBMISSION`。
- `POST /assignments/{id}/submission` 创建正式提交版本。截止前再次提交会创建新版本。
- 学生完成正式提交后，该最新版本立即对同组其他成员和教师可见，不等待作业截止。
- `GET /assignments/{id}/submissions` 返回教师提交看板。个人作业行同时包含 `peer_grade`、`peer_review_count`、`teacher_grade`、`final_grade` 和 `grade_source`。

## 组内互评

系统只提供组员之间的互评，不提供班级互评，不再创建截止后循环分配。

- `GET /peer-review-assignments?class_id={class_id}` 返回当前学生所在组已有成员提交的个人作业，以及可评价、已评价和待评价人数。
- `GET /assignments/{id}/peer-review` 返回本组除自己外所有已正式提交成员的最新版本、附件和当前学生对该版本已有的评价。
- `POST /assignments/{id}/peer-reviews` 新增或更新评价：

```json
{
  "reviewee_id": "uuid",
  "grade": "A",
  "comment": "完成度高，结构清晰。"
}
```

`grade` 只能是 `A`、`B`、`C`、`D`、`E`。服务端禁止自评、跨组评价和评价未提交的学生。同一评价人对同一提交版本只保留一条评价；被评价人提交新版本后，新版本需重新评价，旧版本评价保留为历史记录。

## 教师评分

教师评分是可选的覆盖值。

- `POST /assignments/{id}/submissions/{student_id}/grade` 对学生最新正式提交保存 A–E 评级和可选评语。
- `DELETE /assignments/{id}/submissions/{student_id}/grade` 清除教师评级，使最终成绩恢复由互评决定。
- 教师在提交看板点击“查看评分”后直接预览首个附件；多文件可在同一预览工作区切换，并可同时保存或清除教师评级。

## 最终成绩

互评等级按 `A=5`、`B=4`、`C=3`、`D=2`、`E=1` 求算术平均，再四舍五入回 A–E。最终成绩遵循以下优先级：

1. 当前提交存在教师评级时，`final_grade` 直接采用教师评级，`grade_source=TEACHER`。
2. 教师未评级且当前提交收到互评时，`final_grade` 采用互评汇总等级，`grade_source=PEER`。
3. 两者都没有时，`final_grade` 和 `grade_source` 均为空。

`GET /grades?class_id={class_id}` 向学生返回自己的最终等级、互评汇总、教师评级和成绩来源。

历史的一对一活动、百分制成绩和小组系数数据仍保留用于读取旧记录，但新作业不再依赖这些流程。
