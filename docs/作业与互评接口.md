# 作业与一对一互评接口

所有路径使用 `/api/v1` 前缀，并沿用会话 Cookie 与写请求 `X-CSRF-Token` 校验。

## 作业和文件

- `POST /assignments`、`POST /assignments/bulk`：`description` 接收 HTML，服务端使用白名单清洗。前端发布流程先传 `publish=false` 创建草稿，附件全部成功后调用 `POST /assignments/{id}/publish`。
- 创建作业时可传 `auto_review_enabled=true`，并同时提供 `auto_review_mode`（`TEAM` 或 `CLASS`）、`auto_review_due_at`，以及 `auto_review_criteria_text` 或标准附件。自动互评只支持个人作业，互评截止时间必须晚于作业截止时间。
- `POST /assignments/{id}/files`：教师默认上传 `ATTACHMENT`；查询参数 `purpose=REVIEW_CRITERIA` 上传互评标准附件；学生固定上传 `SUBMISSION`。单文件上限 100 MB。
- `GET /assignments/{id}/files`：返回 `attachments`、`review_criteria` 和 `drafts`。每项含 `previewable`、`download_only`、`preview_status`。
- `GET /files/{id}/preview`：Markdown 转 HTML 后清洗；PDF/图片使用 `inline`；DOCX/XLSX 返回带 `attachment` 响应头的原文件。
- 学生首次和后续提交均调用 `POST /assignments/{id}/submission`。截止前再次提交会按本次 `file_ids` 创建新版本，因此可以增删附件；不再提供撤回接口。

## 截止后自动互评

启用自动互评的作业发布后状态为 `PENDING`。后台任务在作业截止后锁定该作业，按当时已正式提交学生及其最新版本创建一对一互评；重复执行不会重复创建活动。

- `CLASS`：全班候选人按学号排序成环。
- `TEAM`：每个小组独立成环，少于 2 名候选人的小组记为跳过。
- 全班正式提交人数少于 2 人，或后台执行时互评截止时间已经过去，自动创建状态记为 `FAILED` 并保存原因。
- 成功创建后状态记为 `CREATED`，后续补交、换组或提交新版本不改变本次冻结对象。

## 创建和读取互评

`POST /review-campaigns`：

```json
{
  "assignment_id": "uuid",
  "mode": "TEAM",
  "criteria_text": "按完整性和清晰度评分",
  "criteria_file_ids": ["uuid"],
  "due_at": "2099-01-01T00:00:00+08:00"
}
```

`mode` 为 `TEAM` 或 `CLASS`。活动只能关联已截止的 `INDIVIDUAL` 作业；标准文字和附件至少提供一种。响应包含 `allocated`、`skipped`、`warnings` 和 `assignment_snapshot_at`。

`GET /review-campaigns/{id}/assignment` 仅向学生返回自己的分配：实名对象、冻结的 `submission.version_id` 和文件、标准文字/附件、状态及跳过原因。

`POST /review-campaigns/{id}/reviews`：

```json
{
  "score": 88,
  "comment": "结构完整，论证清晰。"
}
```

服务端从分配表确定被评价人和冻结版本。分数范围为 0 至 100，评语去除首尾空白后必须非空；只接受当前学生自己的 `PENDING` 分配，完成后重复提交返回冲突。

`GET /review-campaigns/{id}/stats` 返回 `assigned_count`、`completed_count`、`skipped_count`、`completion_rate`、跳过明细和平均分。教师作废评价后，对应分配恢复为 `PENDING`，学生可重新提交，仍只保留一条分配关联评价。

旧活动的量表字段和旧请求读取逻辑继续保留；新界面只创建上述一对一活动。
