# 作业与一对一互评接口

所有路径使用 `/api/v1` 前缀，并沿用会话 Cookie 与写请求 `X-CSRF-Token` 校验。

## 作业和文件

- `POST /assignments`、`POST /assignments/bulk`：`description` 接收 HTML，服务端使用白名单清洗。前端发布流程先传 `publish=false` 创建草稿，附件全部成功后调用 `POST /assignments/{id}/publish`。
- 创建作业时可传 `auto_review_enabled=true`，并同时提供 `auto_review_mode`（`TEAM` 或 `CLASS`）、`auto_review_due_at`，以及 `auto_review_criteria_text` 或标准附件。自动互评只支持个人作业，互评截止时间必须晚于作业截止时间。
- `PATCH /assignments/{id}` 可在作业截止且互评活动创建前修改上述互评配置；作业截止、提前关闭或活动已经创建后返回 `AUTO_REVIEW_CONFIG_LOCKED`。
- `POST /assignments/{id}/files`：教师默认上传 `ATTACHMENT`；查询参数 `purpose=REVIEW_CRITERIA` 上传互评标准附件；学生固定上传 `SUBMISSION`。单文件上限 100 MB。
- `GET /assignments/{id}/files`：返回 `attachments`、`review_criteria` 和 `drafts`。每项含 `previewable`、`download_only`、`preview_status`。
- `GET /files/{id}/preview`：Markdown 转 HTML 后清洗；PDF/图片使用 `inline`；DOCX/XLSX 返回带 `attachment` 响应头的原文件。
- 学生首次和后续提交均调用 `POST /assignments/{id}/submission`。截止前再次提交会按本次 `file_ids` 创建新版本，因此可以增删附件；不再提供撤回接口。

## 截止后自动互评

启用自动互评的作业发布后状态为 `PENDING`。后台任务在作业截止后锁定该作业，按当时已正式提交学生及其最新版本创建一对一互评；重复执行不会重复创建活动。

- `CLASS`：全班候选人按学号排序成环。
- `TEAM`：每个小组独立成环，少于 2 名候选人的小组记为跳过。
- 全班正式提交人数少于 2 人，或后台执行时互评截止时间已经过去，自动创建状态记为 `FAILED` 并保存原因。
- 成功创建后状态记为 `CREATED`，后续补交、换组或提交新版本不改变本次冻结对象。

## 创建和读取互评

`POST /review-campaigns`：

```json
{
  "assignment_id": "uuid",
  "mode": "TEAM",
  "criteria_text": "按完整性和清晰度评分",
  "criteria_file_ids": ["uuid"],
  "due_at": "2099-01-01T00:00:00+08:00"
}
```

`mode` 为 `TEAM` 或 `CLASS`。活动只能关联已截止的 `INDIVIDUAL` 作业；标准文字和附件至少提供一种。响应包含 `allocated`、`skipped`、`warnings` 和 `assignment_snapshot_at`。

`GET /review-campaigns/{id}/assignment` 仅向学生返回自己的分配：实名对象、冻结的 `submission.version_id` 和文件、标准文字/附件、状态及跳过原因。

`POST /review-campaigns/{id}/reviews`：

```json
{
  "score": 88,
  "comment": "结构完整，论证清晰。"
}
```

服务端从分配表确定被评价人和冻结版本。分数范围为 0 至 100，评语去除首尾空白后必须非空；首次提交将分配置为 `COMPLETED`，活动截止前再次提交会原位更新同一条有效评价且不重复发送“收到评价”通知，截止或提前关闭后返回冲突。

`GET /review-campaigns/{id}/stats` 返回 `assigned_count`、`completed_count`、`skipped_count`、`completion_rate`、跳过明细和平均分。未发布成绩对应的评价被教师作废后，分配恢复为 `PENDING`，成绩恢复为待处理；已发布成绩对应的评价不能作废。

`POST /review-campaigns/{id}/close` 提前结束活动，并同步调用与后台到期任务相同的幂等成绩生成逻辑。到期任务或提前结束无论重复执行多少次，都只为每名参与者生成一条成绩记录。

旧版自由选择评价对象的创建、批量创建和候选人接口已移除；迁移会删除旧活动及其评价，只保留一对一活动。

## 成绩生成、系数和发布

- `GET /grades/assignments?class_id={class_id}`：教师读取已创建一对一互评的个人作业，以及参与、待处理、可发布和已发布人数。
- `GET /grades/assignments/{assignment_id}`：教师读取作业、小组系数和学生成绩明细。小组归属使用互评创建时保存的快照。
- `PATCH /grades/assignments/{assignment_id}/teams/{team_id}/coefficient`：保存该组草稿系数，正文包含 `coefficient` 和 `version`。系数必须非负、最多两位小数且不设业务上限；版本不一致返回冲突。
- `POST /grades/assignments/{assignment_id}/publish`：发布所有当前可发布记录。重新发布导致已发布最终分变化时，正文 `reason` 至少两个字符；待处理记录不阻止其余记录发布。
- `GET /grades?class_id={class_id}`：学生只获得自己的已发布成绩，草稿、待处理和其他学生记录均不可见。

互评分等于该学生收到的唯一有效评价总分。填写小组系数后，草稿最终分按 `min(互评分 × 系数, 100)` 使用十进制计算，四舍五入保留两位。修改已发布系数只改变草稿值，学生在重新发布前仍看到原已发布系数和最终分。

## 单作业成绩导出

- `GET /exports/grades.xlsx?class_id={class_id}&assignment_id={assignment_id}`
- `GET /exports/grades.csv?class_id={class_id}&assignment_id={assignment_id}`

`assignment_id` 必填，且作业必须属于教师当前可管理的教学班。导出只包含指定作业的全体互评参与者，列为作业、学号、姓名、小组、互评分、小组系数、最终分、状态；待处理、未填系数、未发布和已发布状态均保留，空值不自动填零。
